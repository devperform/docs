title: Admin Setup
description: Configuring repos, engineers, teams, and org settings from the Admin panel.
---

The Admin panel is accessible to the user who claims the admin role. It's where you configure everything DevPerform needs to ingest data and display your team.

## Org settings

Under **Admin → Org Settings** you can configure:

- **Organization name** — the display name shown across the app.
- **Burnout threshold** — the open-PR count that triggers the protective 🔥 overload flag in the team table. Default is **5**.
- **Deploy detection mode** — how [DORA](/metrics/dora) detects deploys: **merges** to the default branch (default, zero-config) or successful runs of a named GitHub Actions **workflow**. In actions mode, set the workflow name.
- **Incident label** — the GitHub issue label DevPerform treats as an incident, used for DORA change-failure-rate and time-to-restore.
- **Survey anonymity threshold** — the minimum responses before [survey results](/surveys/results) are revealed. Default is **4**.

## Repos

Add repos as `owner/repo` (e.g. `acme/backend`). All tracked repos are analyzed together for a given date range. Removing a repo only stops DevPerform tracking it — nothing changes in GitHub. Adding a repo kicks off an immediate background sync.

## Engineer roster

Add engineers with a name and at least one GitHub handle, or **import your whole GitHub org at once** — see [Importing your GitHub org](/admin/import-members). For surveys, also map each engineer's **work email**. See [Engineer Roster](/concepts/engineers) for multiple handles and deactivation.

## Teams

Create a nested team hierarchy to enable team filtering. Teams are optional — skip it and all engineers appear together. See [Teams](/concepts/teams).

## Permissions

The admin can add/remove repos, manage engineers and handles, manage teams, and update org settings. Regular (non-admin) users can view dashboards but not the Admin panel.
